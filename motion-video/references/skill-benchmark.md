# Test changes to the skill

Use when asked to improve the skill or assess whether one brief can produce a film at a supplied quality bar. Do not run this whole evaluation for every ordinary product-video request.

## Define a result that would count

Choose a real product workflow or a user-authorized local fixture. A fixture must actually execute its demonstrated transformation, preserve its input and output, and identify itself as a demonstration. Success on it does not establish behavior on a production app. Do not invent a product for a user who asked for their actual product.

Write a compact test brief with the product URL, audience, output set, reference, allowed resources, and delivery folder. Preserve that brief. Separate three questions:

1. Can the available tools reproduce the reference's difficult motion mechanics?
2. Can an independent run use the skill to produce the complete requested films from the brief?
3. Does perceptual comparison support comparable composition, continuity, readability, pacing, and sound?

Technical possibility is not a guarantee of consistent creative quality. A one-shot test allows the agent's internal reviews and revisions; it does not allow hidden human or parent-agent redesign followed by a claim of an unassisted first result.

## Improve from observed failures

Preserve the previous skill and raw test outputs. Start with a short difficult passage to avoid multiplying an unproven look. Fix a demonstrated cause: missing capture access, repeated camera math, poor type hierarchy, an object jumping between scenes, an unusable soundtrack, or absent perceptual review. Add reusable code only where it removes repeated mechanics. Avoid a fixed visual template or a growing list of universal prohibitions.

For a substantial update, run a fresh agent with the skill, raw product/fixture, supplied reference, and test brief. Do not give it the expected storyboard, intended critique, or earlier agent's answer. Let it render and review internally. Save the first delivered result before providing corrections. Where a baseline comparison is useful, use the same brief and resource budget with the prior skill; otherwise explicitly say the comparison is a static audit rather than a before/after render experiment.

The lead then reviews actual files and source captures. Compare matched moments at equal display width: opening hierarchy, decisive UI action, useful result, hardest transition, and closing hold. Name the weak shot and the observed defect. Do not substitute an unexplained numerical taste score for comparison. If the lead repairs the film, label that as an assisted iteration and rerun a fresh test before claiming independent success.

## Keep the verdict honest

Record the tested skill snapshot, prompt, runtime versions, sources, exact render commands, decode/metadata results, visual samples, and revision history. Test added scripts and meaningful numerical invariants. Verify copied assets and relative links from an isolated project; the task's working directory must not be a hidden dependency.

State these conclusions separately:

- Mechanics demonstrated, including the precise scenes and any effect limitations.
- Product truth demonstrated by source-to-export mapping.
- Independent brief-to-export completion, with internal versus external interventions recorded.
- Creative review completed, with visual, temporal, and listening coverage named separately.

When the review environment cannot perceive continuous video or audio, do the useful local work and identify that missing capability. A playback embed shown to the user does not mean the model heard it. Prepare a concrete option for the missing review: a cleared human listening pass, an available perceptual model, or an explicitly approved external review service. Do not install a new API or incur metered costs without authorization.

Stop repeating the same render when the remaining problem requires unavailable footage, resources, or perception. State the exact missing input and what would be sent or spent. Preserve a playable candidate so the user can make the final decision from evidence. Do not mark reference parity established while a material review gap remains.
